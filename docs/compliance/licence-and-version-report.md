# Licence and version report (C001-T-002)

Date of all checks: 2026-11-20. Change: CHG-001. Task: C001-T-002.
Scope: every licence, version and support claim of C001-ADR-001 to C001-ADR-009 (with their
Amendment 1 sections) and of `10-strategy.md` §4, and every dev tool already installed by
C001-T-001 (see `package.json`).

## How to read this report

- **Primary source** is one of: the registry metadata of the package (`npm view`, PyPI JSON API,
  NuGet nuspec), the licence file shipped in the package or in the project repository, official
  documentation, release schedules (nodejs/Release, Microsoft release metadata, endoflife.date), or
  the git source and documentation at the tags `v2.34.0` and `v2.56.1` (the latest release on
  2026-11-20).
- **Outcome** is one of:
  - `confirmed`: the source states the value;
  - `confirmed, note`: it holds, with a point later tasks must respect;
  - `failed, D-nnn`: the claim does not hold; a defect is recorded in `change.md` with `sdd defect add`;
  - `not verifiable here`: the reason is given; nothing is marked confirmed that was not checked;
  - `pending T-005/T-006`: a git behaviour that needs an experiment on git 2.34 and on the latest
    release; C001-T-005 and C001-T-006 add their result to the same row.
- No ADR is edited. Dependencies whose claim failed are not added.
- Direct checks run in this task (beyond reading metadata): the five tree-sitter WebAssembly
  grammars were loaded with `web-tree-sitter` 0.27.2 and parsed current syntax; `koffi` 3.3.8 was
  used to call `CredReadW` on Windows 11 against an entry written by `cmdkey`; `npm install` plus
  `npm audit` and the licence check were run on a scratch project holding every candidate
  dependency of the ADRs (not committed).

### Points for P-01 (not defects of fact)

1. **Copyleft under Vite 8 (D-011).** Constitution, forbidden technologies: "GPL, AGPL, LGPL, SSPL and
   similar". MPL-2.0 is file-level copyleft. `lightningcss` is a build-time dependency of Vite 8 (not
   shipped in the package), but NFR-D-03 counts the dependency tree. Options: pin Vite 7.3.8 and
   `@vitejs/plugin-react` 5.2.0 (tree is permissive, 0 advisories), or accept MPL-2.0 for a build tool
   by an amendment of the constitution. The allowlist rejects MPL-2.0 today.
2. **Permissive licences that OSI has not approved (row X-02).** NFR-D-03 says "OSI-approved
   permissive". The current dev tree holds BlueOak-1.0.0 (14 packages of the npm-ecosystem tool
   chain, for example `minimatch`, `glob`), CC0-1.0 (`spdx-license-ids`) and CC-BY-3.0
   (`spdx-exceptions`, data). `licence-allowlist.json` lists them apart (`permissiveNotOsiApproved`)
   and `npm run licence-check` prints a note for each. They are dev-only and none is shipped. P-01
   confirms whether this reading of NFR-D-03 is accepted, or the tools that bring them are replaced.
3. **Node.js 26 is an LTS line since 2026-10-28 (row R-03).** `10-strategy.md` §4 names 22 and 24.
   Both are supported (row R-01, R-02), so the assumption holds; the CI matrix and the supported-lines
   text of the release notes may add 26.

Findings:

- **D-008 confirmed.** On git 2.34.0 `core.fsmonitor=false` starts a program (two `run_command`
  entries in the trace: the shell and the program `false`); the empty value `core.fsmonitor=` starts
  none, and gives the same result on 2.45.1 and 2.56.1. The adapter uses the empty value
  (`src/core/git/process.ts`, `HARDENING_CONFIG`).
- **`core.untrackedCache=false` (A1.3, row G-17).** The fixture does not enable an untracked cache,
  so what was shown is that no read operation of the adapter writes the repository; that the option
  removes an enabled untracked cache from a read is not shown by experiment. Row G-17 stays pending
  for that part (C001-T-006).
- **`ls-files -m` is refused by the runner.** Comparing content for the modified list can run a
  clean filter; the allowlist of the runner rejects it, and `git status`, `diff`, `diff-files`,
  `diff-index`, `update-index` and every other command outside the read list (A1.2). `log` and
  `diff-tree` are accepted without the options that generate a content diff (textconv).
- **`GIT_NO_LAZY_FETCH=1`** (git 2.44 and later) is set in addition to `protocol.allow=never`; on
  2.34.0 `protocol.allow=never` alone stopped the lazy fetch.
- **Message of a refused repository.** For an unknown extension, git 2.34.0, 2.45.1 and 2.56.1 print
  `fatal: unknown repository extension found:` and the extension name on the next, indented line.
  The adapter's "first error line" therefore takes the first line with its indented continuation
  lines (spec defect raised: C001-TS-166 expects the first line to name "futureformat").
- **Environment.** With each variable of the "Removed" list set to a decoy repository, index, object
  store, graft file, shallow file or configuration file, every read through the adapter returned the
  target's data on the three versions; a plain git command with `GIT_INDEX_FILE` or `GIT_DIR` set read
  the decoy. From a real `pre-commit` hook (`git commit -- <path>`, `GIT_INDEX_FILE` naming the
  temporary index) the adapter's index read equalled the repository's own index and a plain `git ls-files`
  of the hook read the temporary one.
