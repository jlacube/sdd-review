# R-001 — Landscape of tools for reviewing large (AI-generated) code changes

## Question
Brief (verbatim): "Produce a wide, sourced survey of existing solutions that help a human review large code changes, especially those produced by AI coding agents. Cover at least: (a) AI PR reviewers and review bots (e.g. CodeRabbit, GitHub Copilot code review, Graphite/Diamond, Qodo/PR-Agent, Greptile, Sourcery, Ellipsis, Cursor BugBot); (b) review UIs and workflows for large changes (stacked diffs: Graphite, Sapling/ReviewStack, Phabricator; Reviewable, Gerrit; semantic/structural diff tools such as difftastic, SemanticDiff); (c) review surfaces inside agent tools (Claude Code, Cursor, Copilot agent mode, Devin, Codex, Jules, Kiro) — how they present a change for acceptance. For each: what it does, review unit (line, hunk, file, intent), how it scales with change size, spec/intent awareness, deployment (SaaS/local/OSS + licence), notable UX ideas worth copying, and limits. End with a comparison table and the gaps none of them fills for a single developer accepting a very large agent change."

Why asked: ideation step 3 of CHG-001. P-01 answered (questions-log, round 1) that the primary reviewer is the developer reviewing agent output locally, that specs are used when present, that the survey is wide, and that the goal is a disruptive review workflow and UI because the number and size of changes grow fast. This note feeds the options analyses that follow. Out of scope here: SDD/spec tools and academic research on review paradigms (a parallel note covers them); no form factor is recommended.

## Method
- Routing: the question is about products and market, so the first source is web search, then fetching the primary pages found. Context7 was not used (no named library API is asked about). DeepWiki was called once, for `facebook/sapling`, because the question concerns how a public repository presents stacked review; the answer was partial (it could not describe ReviewStack's UI or its licence) and was completed from the vendor blog.
- About 45 searches and fetches on 2026-11-17: vendor documentation and pricing pages first (CodeRabbit, GitHub, Cursor, Graphite, Greptile, Sourcery, Qodo, Devin, Claude Code, VS Code, Kiro, Jules, Codex, Reviewable, Gerrit, difftastic, SemanticDiff), then repositories (PR-Agent, Phorge, Gerrit, tuicr, Plannotator), then secondary coverage only where no primary page was reachable.
- Caveat on method: the fetch tool returns a summary produced by a small model, not the raw page. Facts that matter to a decision (limits, licences, prices) should be re-read on the vendor page before they are relied on.
- Not reached: Phabricator/Phorge Differential documentation (only the Phorge repository page and a search result were read), Ellipsis pricing and size limits (vendor docs page lists topics without detail), Devin sessions as a code-delivery surface (only Devin Review was documented), Cursor's agent accept/reject controls, Codex `/review` slash-command behaviour, Qodo 3.0 (a search result exists; the page opened did not describe it).
- Today's date and access date for every source: 2026-11-17.

## Findings

### A. AI PR reviewers and review bots

- CodeRabbit reviews pull requests, the IDE and a CLI (pre-commit, usable alongside Claude Code, Cursor, Codex). It supports GitHub, GitLab, Azure DevOps and Bitbucket, plus Jira and Linear, and lists PR triage (ranking the PR queue by value and risk). — sources: https://docs.coderabbit.ai/overview/introduction (2026-11-17) — confidence: medium (vendor overview; no detail on review unit or size handling)
- CodeRabbit "Change Stack" (announced 2026-05-13, preview, free for a limited time) re-presents a PR as stack → numbered layers → files → line ranges. Layers group a contract, its implementation and its tests by meaning rather than directory; dependencies between layers are recorded explicitly; summaries and findings attach to ranges; some layers get a generated sequence, state or ER diagram. Three-panel UI (layer list, diff, per-range context), keyboard J/K/Z, mark-as-viewed, draft review submitted to GitHub from the tool, snapshot selector with a staleness flag when the PR moves on. Grouping is model-generated and may differ between runs; excluded files do not appear; no size limit or scaling data is stated; the "20 minutes to 30 seconds" orientation claim is unevidenced vendor copy. — sources: https://docs.coderabbit.ai/change-stack (2026-11-17), https://www.coderabbit.ai/blog/introducing-change-stack-the-first-ai-native-code-review-interface (2026-11-17) — confidence: high (two vendor pages agree on the behaviour; the benefit claim is unevidenced vendor copy and is not relied on)
- CodeRabbit checks a PR against linked issues: GitHub/GitLab references and Jira/Linear keys are detected; for Jira and Linear an issue is either the PR's target (adds requirements) or background context; unaddressed requirements are flagged. This is the nearest mainstream "intent awareness", and it works at issue level, not requirement-ID or acceptance-scenario level. — sources: https://docs.coderabbit.ai/issues/pr-validation (2026-11-17, returned by search; summary taken from the search answer, page not opened directly) — confidence: medium (search-returned primary docs, not fetched)
- GitHub Copilot code review: review unit is the pull request; available on GitHub.com, mobile, CLI, VS Code, Visual Studio, Xcode, JetBrains and Azure DevOps (preview). Effort levels Lite (about $0.25 per review), Balanced (about $1.50), Max (preview, about $10). Excludes dependency manifests, logs and SVG. Reads `.github/copilot-instructions.md`, path-specific instruction files and `AGENTS.md` from the PR head branch. Gathers repository context through GitHub Actions; can hand suggestions to the Copilot cloud agent, which opens a fix PR. No hard size limit stated; cost rises with PR size. Proprietary SaaS. — sources: https://docs.github.com/en/copilot/concepts/agents/code-review (2026-11-17) — confidence: high (official GitHub documentation)
- Graphite: stacked-PR workflow (CLI `gt`, VS Code extension, stack-aware merge queue, PR inbox) plus an AI reviewer (Diamond, renamed Graphite Agent on 2025-10-08) and in-PR chat. Large changes are handled by splitting them into small dependent PRs, not by re-presenting one big diff. Plans (official pricing page): Hobby free (personal repos, limited AI reviews), Starter $20, Team $40 (unlimited AI reviews, customisation, merge queue), Enterprise custom, per user, billed annually. Proprietary SaaS, GitHub-centred. Vendor claims under 3% false positives without method. — sources: https://graphite.com/guides/graphite (2026-11-17), https://graphite.com/pricing (2026-11-17), https://graphite.com/blog/making-ai-code-review-accessible (2026-11-17, search result only) — confidence: high (features and prices come from Graphite's own pages; the false-positive figure is unmeasured vendor copy and is not relied on)
- Cursor announced on 2025-12-19 that it would acquire Graphite, stating that reviewing, merging and collaborating are the bottlenecks as code is written faster; Graphite stays independent for now and the plan is to link local development with PRs. A first integration (Cursor Cloud Agents inside Graphite, 2026-03-02) is reported by a secondary source; a planned merge of Graphite's reviewer with Bugbot is a stated direction, not a confirmed product. — sources: https://cursor.com/blog/graphite (2025 announcement, read 2026-11-17), https://graphite.com/blog/cursor-cloud-agents (2026-11-17, search result only) — confidence: medium (announcement is primary; the integration status rests on one secondary search result)
- Qodo / PR-Agent: PR-Agent is an MIT-licensed open-source agent (commands `/review`, `/describe`, `/improve`, `/ask`), run as a GitHub Action, CLI (`pip`), Docker or webhook, on GitHub, GitLab, Bitbucket, Azure DevOps and Gitea, with any LLM including local ones through LiteLLM; it uses a "PR compression" strategy for large PRs (mechanism not described on the page). It is now community-owned and is not the Qodo commercial product. Qodo 2.0 (Feb 2026, commercial) splits review across specialist agents, adds a judge agent that deduplicates and filters, and a context engine using codebase and PR history; its output includes "requirement gaps" but the source of requirements is not described; its F1 of 60.1% comes from Qodo's own benchmark. A Qodo page states that existing `AGENTS.md`, `CLAUDE.md` and `.cursor/rules/` files are imported as rules. — sources: https://github.com/qodo-ai/pr-agent (2026-11-17), https://www.qodo.ai/blog/introducing-qodo-2-0/ (2026-11-17), https://www.qodo.ai/?p=22522 (2026-11-17) — confidence: medium (PR-Agent facts are primary; Qodo 2.0 facts and its benchmark are vendor-run)
- Greptile: indexes the repository into a graph (files, functions, dependencies) so reviews see beyond the diff; parallel agents; plain-English custom rules; learns from PR comments; TREX agent writes and runs tests in a sandbox; hands off to Claude Code, Cursor, Codex or Devin and offers an MCP server. GitHub and GitLab only. Cloud or self-hosted (Docker Compose or Kubernetes, bring-your-own LLM, air-gapped available). Starter free for one developer with 50 credits per month; Pro $1 per credit (base review 1 credit, Plus 3, Apex 10). Proprietary. — sources: https://www.greptile.com/?format=markdown (2026-11-17) — confidence: medium (vendor page, single source; third-party prices conflict)
- Sourcery: automatic PR review that posts a PR-description summary (purpose and risk), a "reviewer's guide" mapping the change file by file with verification hints, inline comments with one-click fixes, and a status check that can gate merges. Skips drafts, dependency-bot PRs and PRs whose diff exceeds the plan's size cap. GitHub and GitLab, including self-managed. Plans: Open Source free for public repos, Pro $12, Team $24, Enterprise custom (self-hosting, bring-your-own LLM key). Proprietary. — sources: https://docs.sourcery.ai/Code-Review/ (2026-11-17), https://www.sourcery.ai/pricing (2026-11-17) — confidence: high (docs and pricing page are the vendor's own and agree)
- Ellipsis: the vendor's current documentation describes an agent platform (saved agents, sessions, Claude Code/Codex/Gemini CLI harnesses, GitHub code review on each push, spend budgets); the older "PR review bot" description and prices ($20 per developer, or $0.25 per review) come only from directories and an undated blog result and conflict. Review unit, size handling, licence and deployment could not be established. — sources: https://www.ellipsis.dev/docs (2026-11-17), https://toolradar.com/tools/ellipsis-ai/pricing (2026-11-17) — confidence: low (vendor docs and directories conflict; no review detail found)
- Cursor Bugbot: reviews PR diffs, incrementally by default (only changes since the last review); skips PRs above a size limit measured in changed lines and diff characters, and asks the author to split the change (skipped runs cost nothing); ignores `linguist-generated` files; rules from `.cursor/BUGBOT.md`, team rules, learned rules (from merged or closed PR activity) with a 100,000-character cap; Autofix spawns a Cloud Agent (up to 3 attempts per PR); supports GitHub, GitLab, Bitbucket, Azure DevOps; config is read from the base branch so a PR cannot change its own review rules; usage-based billing. A June 2026 update added a pre-push `/review` command (Cursor 3.7+) and skips a later PR review when the diff was already reviewed locally. — sources: https://cursor.com/docs/bugbot (2026-11-17), https://cursor.com/de/changelog/bugbot-updates-june-2026 (2026-11-17) — confidence: high (Cursor's own documentation and changelog)
- Cubic (a further reviewer found while searching): "intelligent diff ordering" groups a PR's files, names and explains each group, puts behaviour-defining code (schemas, API contracts, core logic) first and tests and generated files last, and on PRs above 50 files shows one group at a time instead of loading everything. — sources: https://docs.cubic.dev/code-review-platform/intelligent-diff-ordering (2026-11-17) — confidence: medium (vendor documentation for the behaviour; deployment and licence were not checked)
- Devin Review (Cognition): "Guide view" groups related edits across files with explanations and shows moved or copied code as a move; a file-tree view shows the ungrouped diff. Bug Catcher flags bugs (with a failure scenario and fix), "investigate" and "informational" flags, and security findings with CWE identifiers; repeated reviews mark resolved issues; chat can edit and commit to the PR branch. Starts from a `/devin review` comment, by replacing `github.com` with `devinreview.com`, or from the Devin app; billed in ACUs; public PRs viewable without an account. The docs describe only hosted workflows, no local mode. — sources: https://docs.devin.ai/work-with-devin/devin-review (2026-11-17) — confidence: high (vendor documentation)
- Claude Code managed Code Review (Team and Enterprise, GitHub only): several agents examine the diff and surrounding code in parallel, a verification step filters false positives, findings are deduplicated, ranked by severity and posted as inline comments with a check run that never blocks. Quick, Standard and Deep levels. Reads the diff and surrounding code but does not build or run the code. Runs on Anthropic infrastructure, not self-hosted environments, and is unavailable under Zero Data Retention. `REVIEW.md` is read from the base branch only. — sources: https://code.claude.com/docs/en/code-review.md (2026-11-17) — confidence: high (official Claude Code documentation)

### B. Review UIs and workflows for large changes

- Stacked diffs (Graphite, Sapling): the answer to size is to avoid large reviews by slicing work into dependent units reviewed and merged in order. Graphite's pages describe the mechanism but give no size thresholds. — sources: https://graphite.com/guides/graphite (2026-11-17) — confidence: medium (vendor description; no evidence on effect)
- Sapling and ReviewStack (Meta, announced 2022-11-15): Sapling is a Git-compatible client; ReviewStack is a "demonstration" web UI for GitHub PRs that reviews each commit in a stack separately, because "many external review tools are optimized for reviewing the entire pull request at once". Meta's post names no licence and says the server and virtual file system are not released. The repository's own files declare mixed licences: at least one Sapling Python file states GNU GPL version 2, while the VS Code extension and some Rust crates declare MIT; no repository-wide licence was established. A 2022 user report calls ReviewStack slow and occasionally wrong; its current status was not found. — sources: https://engineering.fb.com/2022/11/15/open-source/sapling-source-control-scalable/ (2026-11-17), DeepWiki answer for facebook/sapling https://deepwiki.com/search/014bf606-1447-4586-bc66-87846364525c (2026-11-17), https://sia.hackernoon.com/experimenting-with-sapling-the-new-git-client-from-meta (2026-11-17, search result only) — confidence: low (the design is from Meta's post, but the licence is inferred by DeepWiki from file headers and no root licence was seen)
- Gerrit: one change equals one commit; amended commits add patch sets; dependent changes form a chain shown in "Related Changes"; reviewers vote on labels and a change is submittable when label rules are met. Review unit is therefore the commit, and large work is expressed as a series. Apache 2.0, self-hosted OSS. — sources: https://gerrit-review.googlesource.com/Documentation/intro-user.html (2026-11-17), https://github.com/GerritCodeReview/gerrit (2026-11-17) — confidence: high (project documentation and repository page)
- Phabricator Differential / Phorge: Phorge is the community-maintained fork of Phabricator, Apache 2.0, self-hosted; Differential's unit is the "revision" with a pre-push review workflow. Stacked-diff support is discussed in a Phorge task (T15410) whose outcome was not read; a Graphite article calls Differential poorly maintained, which is a competitor's marketing claim. Phabricator itself is not covered further. — sources: https://github.com/phorgeit/phorge (2026-11-17), https://we.phorge.it/project/profile/103/ (2026-11-17, search result only) — confidence: low (thin evidence on Differential specifics)
- Reviewable: GitHub-only review UI; tracks, per file and per reviewer, which revision was reviewed, shows net changes since you last looked, and tracks the disposition of each discussion thread until resolved. Code stays on GitHub. Licence and deployment not stated in the pages read; pricing from third parties only (a free tier for public/personal repos; paid per contributor). — sources: https://docs.reviewable.io (2026-11-17), https://docs.reviewable.io/files (2026-11-17, search result only) — confidence: medium (features from vendor docs; pricing, licence and deployment not established from a primary page)
- difftastic: structural diff using syntax trees (30+ languages) so moved or reflowed code is not reported as removed and added lines; falls back to a line diff with word highlights for unknown languages or extremely large files; plugs into git as `diff.external`. MIT, local CLI. It produces a view, not a patch, and does no grouping, ranking or explanation. — sources: https://difftastic.wilfred.me.uk/introduction.html (2026-11-17), https://difftastic.wilfred.me.uk/git.html (2026-11-17) — confidence: high (project manual, version 0.73.0)
- SemanticDiff: language-aware diff as a VS Code extension (also on Open VSX) and a GitHub app; hides whitespace, optional commas and redundant parentheses, shows moved code and changes made inside moved code, groups changes belonging to one refactoring; hiding whole refactorings is "coming soon"; 14+ languages. GitHub app pricing: free for up to 3 seats and for open source, Professional €7–9 per seat per month. Licence terms and local-versus-cloud processing are not stated on the pages read. — sources: https://semanticdiff.com/ (2026-11-17), https://semanticdiff.com/pricing/ (2026-11-17) — confidence: medium (vendor pages; licence and processing location not stated)
- Local review tools for agent output (found while searching): tuicr is an MIT terminal review UI (vim keys) for uncommitted changes, commit ranges or remote PRs on git, jj and Mercurial; it tracks review progress per file or hunk across sessions and copies comments as a numbered markdown list to paste into any agent. Plannotator (Apache-2.0 or MIT) opens a browser review UI served from a local server for an agent's plan and for local or PR diffs; comments and approve/deny decisions flow back into the agent session (Claude Code, Codex, Gemini CLI, OpenCode); optional sharing contacts external services. — sources: https://github.com/agavra/tuicr (2026-11-17), https://github.com/backnotprop/plannotator (2026-11-17) — confidence: medium (single repository page each; no usage data)

### C. Review surfaces inside agent tools

- Claude Code (local CLI/desktop/IDE): every prompt creates a checkpoint (100 most recent kept, about 30 days retention); `/rewind` restores code, conversation or both. Checkpoints do not cover files changed only through Bash, most subagent edits, external edits or symlinks, and are "not a replacement for version control". `/code-review` (alias `/review`) runs a background subagent over the current branch, a PR, a path or a commit range, reports text findings, optionally applies fixes (`--fix`) or posts comments (`--comment`); effort levels trade false positives for coverage; findings are capped (32 in the findings tool). The desktop app shows a per-file diff view, lets the user add inline comments on lines and send them all to Claude, and walks through review findings one at a time ("Fix this one", "Apply fixes"). Review unit: line comments over a per-file diff, findings by file. — sources: https://code.claude.com/docs/en/checkpointing (2026-11-17), https://code.claude.com/docs/en/code-review-local (2026-11-17), https://code.claude.com/docs/en/desktop.md (2026-11-17) — confidence: high (official Claude Code documentation)
- Cursor agent: edits are applied automatically with no approval step described; checkpoints are created before significant changes, stored locally and separate from Git, restoring reverts files only. A live diff view shows changes as they happen; after a task, Review → Find Issues has the agent analyse its proposed edits line by line, and Agent Review in Source Control compares all local changes against the main branch. Per-file or per-hunk accept/reject controls were not found in the pages read. — sources: https://cursor.com/docs/agent/overview (2026-11-17), https://cursor.com/docs/agent/review (2026-11-17) — confidence: medium (absence of controls not proven)
- GitHub Copilot agent mode in VS Code: edits are written to disk at once and tracked as a "working set" of pending reviews; Keep or Undo applies to one change, one file or all; an editor overlay moves between edits; a multi-diff editor opens from a pill showing file count and diff stats; staging in Source Control keeps the matching edit; checkpoints snapshot files before each request. Changes made through the terminal are not in the working set and must be reviewed separately; glob patterns can force diff-and-approval for chosen files. Review unit: change, file or whole set. — sources: https://code.visualstudio.com/docs/copilot/chat/review-code-edits (2026-11-17) — confidence: high (official VS Code documentation)
- GitHub Copilot cloud agent: works in a cloud environment on one repository and one branch (GitHub Actions sessions are capped at 59 minutes), produces one PR per task, exposes session logs ("Logs do not replace your own review and testing"), and relies on the PR review flow, including Copilot code review, for acceptance. — sources: https://docs.github.com/en/copilot/concepts/agents/cloud-agent/about-cloud-agent (2026-11-17) — confidence: high (official GitHub documentation)
- OpenAI Codex: the IDE extension shows a summary and a "focused diff" next to the source, per-file line stats, an Undo button, selective keeping of edits and a follow-up box; Git checkpoints before and after tasks are recommended; larger work can go to Codex cloud. `codex review` is a non-interactive CLI command that reviews uncommitted changes, a base-branch diff, a commit, or custom instructions (one target per run). A GitHub PR review is triggered by an `@codex review` comment (secondary sources only). — sources: https://learn.chatgpt.com/docs/codex/ide (2026-11-17), https://learn.chatgpt.com/docs/developer-commands?surface=cli (2026-11-17), https://inventivehq.com/knowledge-base/openai/how-to-use-codex-for-code-review (2026-11-17) — confidence: medium (two official pages; the GitHub-comment trigger rests on a secondary result)
- Jules (Google): plan approval before any code changes ("Give me a plan"); during work an activity feed with mini diffs; a full-screen diff editor over the files Jules changed; chat for revisions; a completion summary with files changed, lines and runtime; "Publish branch" or "Publish PR" to GitHub. — sources: https://jules.google/docs (2026-11-17), https://jules.google/docs/code/ (2026-11-17) — confidence: high (vendor documentation)
- Kiro: Autopilot (default) versus Supervised mode. In Supervised mode the agent pauses after each turn that edits files; since version 0.8 (2025-12-18) each changed file appears as a card with its line counts, "View diff", accept and reject, plus Accept all and Reject all; a rejection reverts automatically; checkpoints per prompt restore code and conversation. Specs (requirements.md, design.md, tasks.md) have a Markdown Review where the user comments on exact passages and sends them to Kiro in one batch; task execution shows per-task status and runs independent tasks in waves from a dependency graph. The documented review surface for code is per file (per hunk is stated only in a search summary). The spec side is reviewed as text before generation; code review is not linked to tasks in the pages read. — sources: https://kiro.dev/changelog/web-tools-subagents-contextual-hooks-and-per-file-code-review/ (2026-11-17), https://kiro.dev/docs/specs/ (2026-11-17), https://kiro.dev/docs/chat/checkpoints/ (2026-11-17) — confidence: medium (changelog and spec page are primary; per-hunk and checkpoint details come from search summaries)
- Devin as a code-delivery surface (sessions that open PRs) was not documented in the pages read; only Devin Review (above) was verified. — sources: https://docs.devin.ai/work-with-devin/devin-review (2026-11-17) — confidence: low (gap)

### D. Cross-cutting observations

- Size is handled mostly by refusing or splitting: Bugbot skips PRs above its size cap and asks for a split; Sourcery skips PRs above the plan cap; Copilot excludes some file types; Claude Code findings are capped; Graphite and Sapling rely on stacks of small PRs. Only CodeRabbit Change Stack, Devin Review's Guide view and cubic restructure a single large diff into ordered groups. — sources: https://cursor.com/docs/bugbot (2026-11-17), https://docs.sourcery.ai/Code-Review/ (2026-11-17), https://docs.coderabbit.ai/change-stack (2026-11-17), https://docs.devin.ai/work-with-devin/devin-review (2026-11-17), https://docs.cubic.dev/code-review-platform/intelligent-diff-ordering (2026-11-17) — confidence: medium (synthesis across vendor pages; no cross-tool measurement)
- Spec awareness is thin across reviewers: instruction files (`AGENTS.md`, `CLAUDE.md`, `REVIEW.md`, `.cursor/BUGBOT.md`, Copilot instructions) steer review style; issue-level checks exist (CodeRabbit linked issues; Qodo "requirement gaps"). No reviewer was found that maps hunks to requirement IDs or acceptance scenarios, or reports behaviour that no spec item covers. Kiro generates from specs but its documented code review is not linked back to them. — sources: https://docs.coderabbit.ai/issues/pr-validation (2026-11-17), https://www.qodo.ai/blog/introducing-qodo-2-0/ (2026-11-17), https://kiro.dev/docs/specs/ (2026-11-17), https://docs.github.com/en/copilot/concepts/agents/code-review (2026-11-17) — confidence: medium (absence of evidence across many pages, not a proof of absence)
- Grouped, explained review UIs (Change Stack, Devin Review, cubic) are PR-hosted SaaS; Devin's docs describe no local mode and Claude Code's managed review cannot run in self-hosted environments. Local pre-commit review exists mainly as `/review` style commands (Claude Code, Cursor, Codex) that produce findings, and as small OSS tools (tuicr, Plannotator) that give a diff UI and a feedback loop. — sources: https://docs.devin.ai/work-with-devin/devin-review (2026-11-17), https://code.claude.com/docs/en/code-review.md (2026-11-17), https://github.com/agavra/tuicr (2026-11-17), https://github.com/backnotprop/plannotator (2026-11-17) — confidence: medium (vendor and project pages agree; no cross-tool measurement)
- Change tracking inside agent tools has holes that a reviewer can fall into: Claude Code checkpoints and the VS Code working set both miss terminal or Bash-made changes, and Claude Code misses most subagent edits. A review tool built on git state (working tree versus base) does not share this blind spot. — sources: https://code.claude.com/docs/en/checkpointing (2026-11-17), https://code.visualstudio.com/docs/copilot/chat/review-code-edits (2026-11-17) — confidence: high (two official documentation pages state the limits)
- Persisted review state is per file or per hunk at best (Reviewable per file revision and reviewer, tuicr per file or hunk across sessions, CodeRabbit mark-as-viewed, snapshot staleness flag); none found records a verdict per intent or requirement. — sources: https://docs.reviewable.io (2026-11-17), https://github.com/agavra/tuicr (2026-11-17), https://www.coderabbit.ai/blog/introducing-change-stack-the-first-ai-native-code-review-interface (2026-11-17) — confidence: medium (three independent product pages; absence claim is not proof)
- Vendors position AI review as a complement: GitHub says its feedback must be validated and supplemented with human review, and Claude's managed review never approves or blocks a PR. Accuracy claims (Qodo F1 60.1%, Graphite under 3% false positives, Bugbot gains) are vendor-run and unverified. — sources: https://docs.github.com/en/copilot/concepts/agents/code-review (2026-11-17), https://code.claude.com/docs/en/code-review.md (2026-11-17), https://www.qodo.ai/blog/introducing-qodo-2-0/ (2026-11-17) — confidence: medium (primary pages for the positioning; the accuracy figures are vendor-run)

### E. Comparison table

Review unit: L line, H hunk, F file, C commit/PR, G semantic group, I intent. Licence flag: PERM = permissive OSI licence; PROP = proprietary hosted service (terms not reviewed); COPYLEFT? = copyleft component present (forbidden as a dependency by the constitution). "Tool as dependency" matters only if the change would embed or call the code; using a SaaS as inspiration is not constrained.

| Tool | Category | Review unit | Scaling approach | Spec / intent awareness | Deployment and licence | Idea worth copying | Main limit |
|---|---|---|---|---|---|---|---|
| CodeRabbit (Change Stack) | PR reviewer + UI | G (layers, ranges), L comments | Groups one large PR into ordered layers | Linked issues (Jira, Linear, GitHub) checked for acceptance criteria | SaaS, PROP | Layers ordered by explanation, per-range summary, staleness flag | Model-generated grouping varies by run; PR-hosted; no size data |
| Copilot code review | PR reviewer | C (PR) | Cost scales with size; excludes some files | Instruction files only | SaaS (GitHub), PROP | Effort levels with stated cost | No hard limit stated; no structure for big diffs |

## Confidence
Overall: medium. Feature descriptions come from vendor documentation fetched on 2026-11-17 and are strong for what each tool says it does. They are weak on measured effect: no independent evaluation of grouping accuracy, review time or false-positive rates was found, and benchmark numbers are vendor-run. Prices and plans change quickly and conflict across third-party listings; official pages were used where reachable. Gaps in the table (Ellipsis, Differential, Devin sessions, Cursor accept controls, Codex `/review` slash command) are marked. What would raise confidence: opening the vendor pages directly rather than through summarised fetches, trying the three grouped-review UIs on a real 50+ file agent change, and checking the licences of SemanticDiff, Reviewable and Sapling's root licence file.

## Implications
- Space left open: grouped, explained review exists (Change Stack, Devin Review, cubic) but as PR-hosted SaaS; local pre-commit review exists but without grouping, ranking or spec links. A local, spec-aware, grouped review for one developer is not served by a single product found.
- A "disruptive" paradigm has partial precedents to study, not to copy: ordered layers with explanations (CodeRabbit), behaviour-first ordering (cubic), plan approval before code (Jules, Plannotator, Kiro specs), per-turn checkpoints (Claude Code, Cursor, Kiro), review progress state (Reviewable, tuicr), and feedback returned to the agent as a batch (Claude Code desktop, tuicr, Plannotator).
- Because many tools handle size by skipping or splitting, a tool that accepts a single very large diff and still produces a usable structure addresses a gap that the market documents but does not fill.
- Licence risk for reuse: PR-Agent, difftastic, tuicr, Gerrit, Phorge and Plannotator are permissive and could be dependencies or references; Sapling contains GPL-2 files and must be treated as non-dependency material until its licence is clarified. SaaS reviewers cannot be dependencies at all; if a design relies on calling one, that is a cost and data-sharing decision for P-01.
- Risk: any design that relies on AI-generated grouping inherits the non-determinism CodeRabbit documents (regrouping on a later run). Review state must therefore be anchored to a snapshot and flag when it is stale.
- Risk: designs that depend on agent-tool checkpoints for change tracking miss Bash and subagent edits; working-tree versus base-commit comparison avoids this.

### Gaps no surveyed tool fills for a single developer accepting a very large agent change
Each gap is an inference from the absence of a feature across the pages read (confidence: medium to low), not a confirmed fact about every product.
1. Local, pre-commit review that restructures one huge diff into ordered, explained groups (grouped UIs found are PR-hosted; local commands give findings lists).
2. Mapping of changes to specification items (requirement, task, acceptance scenario) and the reverse: flagging code that no spec item covers, and spec items with no corresponding change. Only issue-level checks exist.
3. A durable verdict ledger: accept, reject or defer per group or per intent, with evidence, surviving restacks and later agent runs. Existing state is per file or hunk "viewed" marks.
4. Risk-based triage that tells the developer what needs human eyes and what is mechanical (generated code, moves, renames, formatting), combined across structural diff and AI analysis. Today these are separate tools (SemanticDiff, difftastic, AI reviewers).
5. Review budget awareness: how much of the change has been inspected, what remains, and what confidence that gives. No tool surfaces coverage of the review itself.
6. Comparison of the agent's own account of what it did (summary, transcript, plan) with what the diff actually contains.
7. A review loop that sends structured, batched feedback to the agent and verifies that the next iteration addressed each item (partial precedents: Claude Code desktop, tuicr, Plannotator).
8. Handling of changes invisible to agent checkpoints (shell-made edits, subagent edits) inside the review surface.

## Conflicting evidence
- Graphite pricing: its October 2025 announcement coverage lists Hobby free and Team $40, while a third-party listing says $20 per user per month with a free plan; the official pricing page read today lists Hobby free, Starter $20, Team $40, so the sources agree once the Starter tier is included. Official page preferred.
- Greptile pricing: third-party figures range from $0–30 per user to $150 per month for five developers; the vendor page (credit-based, $1 per credit) was preferred.
- Qodo pricing: third-party sources disagree ($30 per user per month versus credit packs); not relied on. Qodo's own benchmark and an "independent write-up" cite the same F1 figure; treated as one vendor-derived claim.
- Ellipsis: directory descriptions (review bot, $20 per developer) conflict with the vendor's current docs (agent platform); the vendor page was preferred and the rest marked low confidence.
- Kiro: the official changelog says per-file accept and reject; a search summary also says per-hunk. Per-file was used; per-hunk is unconfirmed.
- Sapling licence: Meta's post names none; file headers disagree (GPL-2 versus MIT). Treated as mixed and not usable as a dependency until clarified.
- Codex `/review`: secondary sources disagree on the number of presets (three or four); official command reference names none. Not relied on.
