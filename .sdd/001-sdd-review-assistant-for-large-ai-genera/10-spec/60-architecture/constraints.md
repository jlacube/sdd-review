# C001 — Architecture constraints

C001-CON-01 to C001-CON-08 are defined in `10-context/scope.md` §4 and bind every component. The
constraints below add what the architecture needs on top of them. Choices left to 20-plan are
named in the constraint that bounds them; each needs an ADR there.

| ID | Constraint | Source | Affects |
|---|---|---|---|
| C001-CON-09 | The analysis core imports neither the UI server nor the web client. The CLI loads the UI server only for `review` and `open`. Every analysis and verdict operation is reachable through the core API (C001-IF-003) with the UI neither installed nor running. | C001-DEC-002, C001-CON-03, C001-REQ-913 | C001-COMP-001, C001-COMP-002, C001-COMP-018, C001-COMP-019 |
| C001-CON-10 | The UI server listens on 127.0.0.1 only, checks the Host header of every request, requires the per-start token and the server's own origin on every API request, sends no CORS header and serves pages with a self-only Content-Security-Policy (C001-IF-002). The first version has no remote-access option. | C001-CON-02, C001-NFR-009, C001-NFR-010, C001-DEC-002 | C001-COMP-018, C001-COMP-019 |
| C001-CON-11 | No process of the review assistant opens a connection to a non-loopback address, except the model gateway to the configured cloud provider's endpoint with the cloud opt-in setting: no telemetry, no update check, no download of scripts, fonts or packages at run time, no git network operation. The gateway decides locality from the endpoint text without name resolution: only local sockets, 127.0.0.0/8, ::1 and the host name `localhost` are local, and `localhost` is connected through 127.0.0.1 or ::1, never through the system resolver or DNS (C001-IF-010 §6). | C001-CON-01, C001-NFR-011, C001-NFR-012, C001-DEC-004 | C001-COMP-001 to C001-COMP-019 |
| C001-CON-12 | Every request to a model provider passes through the model gateway, which applies the checks of C001-IF-010 §6 in order; no other component holds a provider client. Model output never feeds clearing, risk scores or verdicts. | C001-DEC-004, C001-CON-05, C001-NFR-012, C001-REQ-405, C001-REQ-412 | C001-COMP-008, C001-COMP-009, C001-COMP-010, C001-COMP-015, C001-COMP-016, C001-COMP-017 |
| C001-CON-13 | All git data is read through the git access port (C001-IF-012) under its safety rules: read-only, no repository-configured program, no network, values checked before use. This includes the data of submodule repositories that fill evidence workspaces (C001-IF-012 G-16). | C001-CON-04, C001-NFR-011, C001-REQ-120, C001-REQ-707 | C001-COMP-003, C001-COMP-004, C001-COMP-006, C001-COMP-011, C001-COMP-013 |
| C001-CON-14 | Git access is implemented by running the git program that the developer installed (C001-ADR-004, accepted). The git program (GPL-2.0) is run only as a separate, developer-installed program, never linked, bundled or redistributed; C001-ADR-004 states that this use is not a forbidden copyleft dependency under the constitution, a reading that covers this use only. Replacing the git program, for example by a git library, needs a new ADR checked against C001-IF-012, and such a library must carry an OSI-approved permissive licence. | Constitution forbidden technologies, NFR-D-03, C001-CON-07, C001-ADR-004 | C001-COMP-003 |
| C001-CON-15 | The review assistant runs on Windows 11 x86-64, macOS 14 or later on x86-64 and arm64, and Ubuntu 22.04 LTS or later on x86-64; the UI runs in the two latest major versions of Chrome, Edge and Firefox. No component relies on a feature one of them lacks; paths, shells, file locks and credential stores have an implementation on each. | C001-NFR-016, C001-NFR-017 | C001-COMP-001 to C001-COMP-019 |
| C001-CON-16 | Review state is kept by the review state store on the local machine, outside the working tree and outside git objects, refs and index, one directory per snapshot. The review record is append-only and every entry of a recorded action is flushed to disk before the action is confirmed; analysis results, samples included, are saved per revision as one complete set before the revision is shown (save, restore and crash-safety design: `architecture.md` §4.2; options considered for where the state is kept: `architecture.md` §4.3). The exact location (for example inside the common git directory or in the user's application-data directory) is chosen by ADR in 20-plan. | C001-NFR-014, C001-REQ-101, C001-REQ-118, C001-REQ-120, C001-REQ-707, C001-REQ-713, C001-REQ-918, C001-REQ-920 | C001-COMP-002, C001-COMP-014 |
| C001-CON-17 | Static analysis is deterministic for a given release, snapshot and configuration: the diff algorithm and the syntax-parser grammars, each grammar at the version pinned for the release (C001-ADR-003), are fixed per release, ties are broken by path then line, and no wall-clock time or random value enters the architecture delta, the intent map or a risk score; run identifiers and timestamps are excluded from comparisons. The only random input is the sample seed drawn when a review is created (C001-INV-16). | C001-NFR-015, C001-REQ-405, C001-REQ-604, C001-ADR-003 | C001-COMP-004, C001-COMP-007, C001-COMP-008, C001-COMP-009, C001-COMP-010, C001-COMP-012 |
| C001-CON-18 | Implementation language, UI stack, syntax parsers, per-test coverage adapters, mutation tools and credential-store access are chosen by ADR in 20-plan, within: one installable package holding CLI, core and UI assets; in-process parsing of the three deep ecosystems; the thresholds of C001-NFR-001, C001-NFR-003, C001-NFR-004 and C001-NFR-018; the UI shipped as static assets served by the UI server. Prerequisites that the developer installs, outside the package: Node.js 22 or later, an LTS line (C001-ADR-001), and git 2.34 or later, run only as a separate program with the hardening profile of C001-ADR-004 (C001-CON-14); a git that cannot be found or started, or whose version is older than 2.34 or cannot be read, stops every command that reads git data with ERR-INTAKE-008 (C001-IF-012 §6). | C001-NFR-001, C001-NFR-003, C001-NFR-004, C001-NFR-008, C001-NFR-018, C001-CON-07, C001-ADR-001, C001-ADR-004 | C001-COMP-001 to C001-COMP-019 |
| C001-CON-19 | Model tasks, test runs, mutation testing and bundle runs never delay the static views: the architecture delta is published when static analysis completes, and later results arrive as new revisions of the review. | C001-NFR-001, C001-NFR-002, C001-NFR-018, C001-REQ-201 | C001-COMP-002, C001-COMP-011, C001-COMP-015 |
| C001-CON-20 | Content of the repository, of named files, of transcripts and of model output is data: the UI renders it as text, never as HTML or script; commands taken from it run only after the developer's confirmation; no component follows instructions found in it. | C001-NFR-010, C001-REQ-511, C001-DEC-003 | C001-COMP-005, C001-COMP-011, C001-COMP-015, C001-COMP-019 |
| C001-CON-21 | Model-provider keys are read only from environment variables or the operating system's credential store, when a request is prepared; they never appear in the repository, logs, analysis results, the review record or the UI. | NFR-D-01, C001-CON-07, C001-REQ-809 | C001-COMP-006, C001-COMP-015, C001-COMP-016, C001-COMP-017 |
| C001-CON-22 | Every evidence run (test command, mutation tool, bundle command) runs in an evidence workspace that holds the snapshot's files and lies on the local machine outside the working-tree root and the git directory, below neither (C001-IF-013 §2). For a run, the review assistant writes, moves and deletes nothing in the working tree, ignored files included, and nothing in the git directory, runs no git command that changes refs, the index or tracked files, and names no working-tree path in what it adds to a command (C001-IF-013 §9 item 1); a git worktree is not used, because creating one writes administration files into the git directory and runs checkout hooks and filters (C001-IF-012 §2). Project code that addresses the working tree on its own (command text, package link, absolute path) is outside this guarantee; the evidence runner observes the working tree and the repository's index and refs during every run and reports changes with ERR-EVID-009, and parts it could not observe for the whole run with ERR-EVID-010 (C001-IF-013 §9 items 2 to 4). No compiled or transformed form of the project's own files (compiler outputs, bytecode, incremental-build state, transform caches) is taken from the working tree into a workspace (C001-IF-013 §2 item 4, C001-REQ-509). A copy of a working-tree file under a clean filter is not such a form: it is the snapshot's own file, copied by the read-only copier of C001-ADR-006 and kept, for a Git LFS file, only when the copy's SHA-256 hash and size equal those that the file's Git LFS pointer file names (C001-REQ-529), and for a file under another filter, only while git's index records it, before and after the copy, as up to date with the blob of its snapshot side under the test of C001-IF-012 §7 item 1 (C001-REQ-527), with the limit of C001-IF-012 §7 item 8 that P-01 accepted with Q-nonlfs-01 (an index entry written or refreshed after an edit, or on Windows a same-size edit with its modification time set back, lets the edited bytes through); a file that fails its check holds its stored form with notice ERR-EVID-013 (C001-IF-013 §2 item 1, C001-REQ-528, Q-filterworkspace-01, Q-cleanfilter-02). A workspace holds no git metadata (C001-ADR-006, accepted; C001-IF-013 §2 item 4), and its submodule paths are filled from the submodules' local repositories through the git access port (C001-IF-012 G-16, C001-IF-013 §2 item 8). Mutation testing runs in a copy of the test run's workspace, which is removed when mutation testing ends (C001-IF-013 §2 item 3). Chosen by ADR in 20-plan: how a workspace is filled (with the content of C001-IF-013 §2 item 1), where it lies, which ignored paths of the working tree (installed dependencies, restored packages, local settings) are made available and how, so that no path the review assistant makes available leads into the working tree; how a Python project's dependencies are provided: third-party distributions from the Python environment the developer's environment selects, and in every run each module of the project that a Python process would import from a working-tree file of the snapshot imported from the workspace instead, so that no editable install, import path or virtual environment pointing at the working tree makes a run execute working-tree files (C001-IF-013 §2 item 7), shown on the Python benchmark change of C001-NFR-005 with the project installed in editable mode from the working tree into the active environment, where passing tests must be recorded for its changed lines and no ERR-EVID-008 raised; how a Node or .NET package link to the working tree is made to load the workspace; how the mutation copy is made self-contained, so that no path in it leads into another evidence workspace, the test run's included, into the working tree or into the git directory (C001-IF-013 §2 item 3), shown on the benchmark change of C001-NFR-005 of each deep ecosystem, with the project installed in editable mode in the test run's workspace where its tests need it installed (`30-nfr/nfr.md` §0), by a mutant applied in the copy that a passing test executing its line kills, by a self-containment check (C001-IF-013 §5 item 4) that reports no file, and by the test run's workspace, ignored paths included, unchanged after mutation testing; how mutation testing keeps capacity free for bundle runs (C001-IF-013 §1 item 4); and the observation mechanism of C001-IF-013 §9 item 3, with the conditions on each operating system of C001-CON-15 that make its observation incomplete (§9 item 4). The ADR measures reset (the copying and hashing of files under a clean filter included), check and observation time against C001-NFR-018 (a) and (c), and the time of the mutation copy against (b), as C001-IF-013 §8 items 1, 2 and 4 place them, and shows by a kill test that an interrupted mutation run leaves the working tree unchanged. Risk for the ADR: workspace preparation and the cold build of the first run in a fresh workspace fall under no threshold of C001-NFR-018 and recur in each review session (C001-IF-013 §8 item 3); the ADR measures both on each benchmark change against the test command in the developer's built working tree and, when C001-AS-08 does not hold, adopts only the mitigations that C001-IF-013 §8 item 3 allows. Risk for the ADR: (c) holds while mutation testing runs (Q-overhead-01), so mutation testing leaves capacity free for bundle runs (C001-IF-013 §1 item 4), which lengthens (b); the ADR measures (b) with that capacity kept free, and (c) both while mutation testing runs and after it has ended, on each benchmark change; when the two thresholds cannot both hold, the conflict goes back to P-01, and the ADR relaxes neither. | C001-REQ-506, C001-REQ-509, C001-REQ-514, C001-REQ-515, C001-REQ-516, C001-REQ-521, C001-REQ-522, C001-REQ-523, C001-REQ-524, C001-REQ-526, C001-REQ-527, C001-REQ-528, C001-REQ-529, C001-CON-04, C001-NFR-014, C001-NFR-018, C001-ADR-006 | C001-COMP-003, C001-COMP-011 |
